# Flow A (new patient + initial evaluation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- The therapist registers a patient with name and WhatsApp only, and the patient gets the welcome.
- The therapist captures the initial evaluation from photos of the clinic's *Historia Clínica*
  or from voice notes, checks it, and confirms. It's saved as structured fields; no photo is
  kept.

**Architecture:** Two deterministic step machines in `lib/agents/therapist/`, `new-patient.ts`
and `initial-eval.ts`, follow Flow B's patterns:
- **Draft row:** the evaluation draft lives in the database (`initial_evaluations.draft`).
- **Atomic writes:** the same RPC pattern as `0002`.
- **Changes:** revise calls declare the paths they change, and `mergeRevision` keeps everything
  else as it was.
- **Pure logic:** parsing, duplicate decisions, gaps, patient-field mapping and formatting live
  in files with no `server-only`, so `npm run check` tests them.

**Tech Stack:** Next.js 16 / TypeScript, Supabase (service role `db()`), OpenAI `gpt-4.1` (Structured Outputs; image input via `image_url` data URLs), Twilio, zod 4.

**Spec:** `docs/superpowers/specs/2026-11-24-flow-a-design.md` (read its Schema section; it is the field list).

## Global Constraints

- es-MX copy following `docs/conversation-design.md`: numbered options with an icon, one
  question per message, echo voice transcripts with ✏️ Corregir, never a dead end.
- Every message is ≤ 1,600 characters. Split, and send the options last (reuse `pack` from
  `note-format.ts`; export it).
- Nothing is saved, and nothing is sent to the patient, before the therapist confirms (Guardar /
  Confirmar). Only a whole-message yes confirms (`isConfirmWord`).
- Never invent. A field marked "niega/negado/ninguno" or crossed out is "Niega"; one not written
  is null.
- No form image is stored by Bitácora. Twilio media for pages is deleted right after a
  successful extraction (best effort), and on Descartar.
- Model: `optionalEnv("OPENAI_EXTRACT_MODEL", "gpt-4.1")`. At most one model call per incoming
  message.
- Migration `0003` is additive. Run it in the Supabase SQL editor before merging, with a
  rolled-back check script.
- Typecheck gate: 0 `error TS` lines. Run `npm run lint` and `npm run check` green.
- Synthetic data only. The public repo never gets a real patient's form, nor the clinic's
  branded template.

## Review Focus

1. **Photos sent as one multi-select** (3 pages arrive at once): all are kept, as "página 1/2/3",
   with none lost (Task 3 SQL test; Task 9 sim).
2. **A number typed in many forms** ("55 1234 5678", "+52 1 55…", "5215512345678", "+1 617…"):
   one stored form; a seed patient's number is always detected as a duplicate (Task 2 checks).
3. **A blurry or partly illegible page:** the review lists "No se pudo leer: …", and fields are
   never guessed (Task 6 smoke + Task 9 sim with the blurry image).
4. **An evaluation confirmed for a patient whose diagnosis/dob/sex the patient or staff already
   filled:** those values are untouched (Task 3 SQL test).
5. **A long evaluation review** (full form): split into messages each ≤ 1,540 characters, options
   last, no section lost (Task 4 check).

### Task 2: Pure intake logic

**Files:** create `lib/agents/therapist/intake-logic.ts`; test `scripts/check-flow-a.mts`.

**Interfaces — Produces:**
- `parsePatientPhone(raw: string | null): string | null`. Returns E.164 in the stored form, or
  null.
  - Keep a leading `+` and digits only.
  - With `+`: `+digits`.
  - Without `+`:
    - 10 digits → `+52…`;
    - 12–13 digits starting with `52` → `+…`;
    - 11 digits starting with `1` → `+…`;
    - anything else → null.
  - Then apply `normalizePhone`. Valid only if `/^\+\d{8,15}$/` matches.
- `type NumberOwner = { kind: "patient"; id; full_name; clinic_id; status: "active"|"discharged"; consent_at: string|null } | { kind: "therapist" }`.
- `classifyNumber(owners: NumberOwner[], clinicId: string): { kind: "new" } | { kind: "therapist" } | { kind: "other_clinic" } | { kind: "existing"; patient } | { kind: "discharged"; patient }`.
  Precedence is therapist, then same-clinic patient (active → existing, discharged → discharged),
  then other clinic, then new.
- `type EvalGap = "chief_complaint" | "pain" | "diagnosis" | "plan"`.
- `evaluationGaps(e: EvaluationExtraction): EvalGap[]`, using the spec's core items, in that
  order.
- `EVAL_GAP_LABELS: Record<EvalGap, string>` = "motivo de consulta", "intensidad del dolor",
  "diagnóstico", "plan de tratamiento".
- `patientFieldsFromEvaluation(e): { diagnosis: string|null; referring_doctor: string|null; dob: string|null; sex: "female"|"male"|null }`:
  - `diagnosis` is `diagnostic_impression ?? pt_diagnosis`;
  - `referring_doctor` is "name (specialty)", or just the name;
  - `dob` only if `isValidDate`.
- `isValidDate(s: string|null): boolean` checks YYYY-MM-DD and that it's a real calendar date in
  the past.
- `displayPhone(e164: string): string`. `+5215512345678` → `+52 55 1234 5678`; others are
  returned unchanged.

### Task 8: Step machines + menu

**Files:** create `new-patient.ts` and `initial-eval.ts`; modify `index.ts`.

**Interfaces — Produces:**
- `startNewPatient(ctx)` / `handleNewPatient(ctx)`, flow `"new_patient"`.
- `startInitialEval(ctx)` (menu: picker first) / `offerEvaluation(phone, patient)` /
  `handleInitialEval(ctx)`, flow `"initial_eval"`.
- Menu item 5: `{ id: "initial_eval", title: "Valoración inicial", icon: "🩺" }`.

**Registration behaviour (spec, Piece 1):**
- **Each message:** prompt → text or voice (voice is transcribed and echoed) → `extractRegistration`
  → `parsePatientPhone`.
- **Missing pieces:** if one is missing, ask only for it ("¿Cuál es su WhatsApp?" / "¿Cuál es
  su nombre completo?").
- **Duplicate check:** `classifyNumber(numberOwners)`:
  - existing → "Ese número ya es de *X*." with 📝 Nota de sesión / 🩺 Valoración inicial /
    🗑️ Cancelar;
  - discharged → ✅ Reactivar / 🗑️ Cancelar;
  - other clinic → the generic message, and the flow ends;
  - therapist → ask for another number.
- **The card:** shown with the `sameNamePatient` warning when there's a match, and
  `REGISTRATION_OPTIONS`.
  - Corregir: `extractRegistration(fix, current)` → the card again.
  - Guardar: `createPatient`. A `"duplicate"` result goes back to the duplicate check.
- **After saving:**
  1. Call `startWelcome` inside try/catch. The Sandbox line is added when
     `!process.env.TWILIO_TEMPLATE_WELCOME`.
  2. Call `offerEvaluation`.
- **Leaving the flow:** "📝 Nota de sesión" on a duplicate hands over to Flow B by calling
  `startSessionNote` with the patient preselected. Add
  `startSessionNoteFor(ctx, patient: PatientRef)` to `session-note.ts`, which calls `beginDraft`.

**Evaluation behaviour (spec, Piece 3):**
- **`choose_source`:** 📷 sends `PHOTO_PROMPT` and moves to `pages`; 🎙️ sends the voice guide and
  moves to `recording`; ⏭️ ends the flow ("Puedes hacerla después desde el menú 🩺."). An image
  at `choose_source` starts the photo path with that page; a voice note starts the voice path.
- **`pages`:** each image is appended, with an ack showing the count, up to 6; past that, "Ya
  tengo 6 páginas; responde Listo". ✅ Listo → "Un momento, leo el formato…":
  1. Download every page.
  2. `extractEvaluation`.
  3. On success, `deleteTwilioMedia` each page, save the extraction and show the review.
  4. On failure, keep the media and offer Listo to retry.
  Text at `pages` gets the re-prompt.
- **`recording`:** like Flow B, with echo and Corregir. Listo → `extractEvaluation({ transcripts })`.
- **`review`:**
  - Confirmar (or `isConfirmWord`) → `confirmEvaluation` → "✅ Valoración inicial guardada en el
    expediente de *X*." and the state ends.
  - Corregir or a plain-words fix → `reviseEvaluation` → `mergeRevision` → the review again.
    Nothing applied → "No entendí qué cambiar…".
  - Descartar → delete media (photo path) and the draft.
- **Stale or confirmed draft:** "Esta valoración ya estaba guardada." or "Esa valoración ya no
  está abierta.", as in Flow B.
