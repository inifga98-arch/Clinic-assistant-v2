# Flow B (session note and home plan) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A therapist picks a patient, records one or more voice or text notes, and gets one
SOAP note and home plan back. They answer up to three questions, correct it in plain words, and
on Confirmar it is locked and the plan becomes active.

**Architecture:**
- A deterministic step machine (`lib/agents/therapist/session-note.ts`) drives the conversation.
- AI calls only transcribe, extract (`extractSoap`) and apply one change (`reviseSoap`).
- The draft lives in `sessions.draft` (jsonb) so it outlives the 30-minute conversation state.
- Three Postgres functions make the writes atomic: append a transcript, merge draft fields,
  confirm.
- Pure logic (matching, missing items, merge, formatting, mapping) sits in files with no
  `server-only` import, so `npm run check` can test it.

**Tech Stack:**
- Next.js 16, TypeScript.
- Supabase (`@supabase/supabase-js`, service role via `db()`).
- OpenAI `gpt-4.1` with `chat.completions.parse` + `zodResponseFormat`, zod 4.
- Twilio via `lib/whatsapp/send.ts`.

**Spec:** `docs/superpowers/specs/2026-11-23-flow-b-design.md`

## Global Constraints

- All user-facing copy in es-MX. One question per message. Options sent with `sendOptions`
  (numbered list) and read with `matchOption`.
- Never invent clinical content: the extraction and revision prompts must say "usa solo lo que
  dijo el terapeuta; si no lo dijo, null o vacío; no escribas una valoración que no dio".
- Nothing reaches the record without the therapist choosing Confirmar.
- At most 3 missing-item questions per note. "omitir" skips the current one.
- A single WhatsApp message must stay at or under 1,600 characters.
- Model: `optionalEnv("OPENAI_EXTRACT_MODEL", "gpt-4.1")`, the same as `lib/agents/patient/activity.ts`.
- At most one model call per incoming message.
- Dates use `clinicToday()` from `lib/agents/patient/time.ts` (America/Mexico_City), not UTC.
- Drafts older than 24 h are never offered.
- Never edit `0001_init.sql`. Migration `0002` is additive and is run in the Supabase SQL
  editor before the PR is merged.
- Shared files (`lib/db/types.ts`, `package.json`): keep changes minimal and name them in the PR.
- Typecheck gate: `npm run typecheck` with 0 `error TS` lines (count them, don't trust the exit
  code through a pipe).

## Review Focus

1. Two voice notes arriving at the same moment during `recording`: both are kept, in
   arrival order (Task 4 SQL test).
2. Confirmar tapped twice, or a stale review: the second tap says "Esta nota ya estaba
   guardada." and no second plan is created (Task 4 SQL test, Task 8 sim script).
3. A long note whose review exceeds 1,600 characters: it is split into messages, each at or
   under 1,600 characters, with the options last (Task 3 test).
4. A voice note sent at `review` (a spoken correction): it is transcribed and applied as a
   correction, not appended as a new note (Task 7 test via the sim script `correction_voice`).
5. "Sin cambios" for a patient with no active plan: the save succeeds, no plan is created, and
   the review says "Plan en casa: sin cambios (no hay plan activo)" (Task 3 test, Task 4 SQL
   test).

- [ ] **Step 3: Picker steps.**
  - **`pick_patient`**, in this order:
    1. A number in range picks that candidate.
    2. A text of 40 characters or fewer with no audio goes to `matchPatients` over
       `clinicPatients`:
       - 1 hit → create the draft and go to recording;
       - 2–8 hits → `disambiguate`, with the labels as options;
       - 0 hits → "No encontré a «X». Escribe el nombre completo." and stay;
       - more than 8 hits → "Hay muchos pacientes con «X». Escribe nombre y apellido." and stay.

       it, keep it as `pending`, and run `namesInText`:

       - otherwise → "Guardé tu nota. ¿De qué paciente es?" plus the picker.

- [ ] **Step 4: Recording and processing.**
  - **At `recording`:**
    - a choice of Listo, `isDoneWord` or `matchOption(..., RECORDING_OPTIONS)` "done" means
      process;

    1. Zero transcripts → "Aún no tengo ninguna nota. Mándala por voz o texto." and stay.

       - null → send the review and go to step `review`.

       intentarlo otra vez." and stay in `recording`.
